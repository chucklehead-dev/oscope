## Crypto provider claim-scope gap

`crypto-provider-is-explicit-and-matches-the-qualified-app-graph` (dependency_resolution_test.clj:170–181) only confirms (a) exactly one `jolt-crypto` root resolves, (b) it matches the explicit pin, and (c) substituting the upstream `5effcc89...` SHA changes the resolved root string. It does **not** compare classpath dependency frequencies before/after adding the explicit pin. So the stronger claim — that making the provider explicit didn't change which physical artifact was already selected transitively (vs. just picking *a* valid one) — is asserted in prose but not verified by this test. That's a real claim-scope gap worth closing with an actual frequency/count comparison test, not a blocker but worth flagging.
